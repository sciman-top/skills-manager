# Model Orchestration

- Source: `presets.json`, `Set-ModelPreset.ps1`, `Start-ModelSlot.ps1`.
- Strict entrypoint: `Start-ModelSlot.ps1`; freeze one route and disable native delegation. Do not substitute a profile-only launch as strict acceptance.
- Runtime: PowerShell 7; no gateway selection, credential changes, daemon, or task replay.
- `presets.json` schema v6 jointly activates GPT-6-luna (`gpt-6-luna`) max, GLM-5.3-Flash xhigh, Claude Haiku 5.5 on medium < high < xhigh, and Gemini 3.8 Flash high (relay catalog slug `gemini-3.8-flash-high`) on Codex. The Codex task map is tiered from the 2026-10-18 real-API evaluation: Haiku medium for quick triage, Haiku high for standard review, GLM xhigh for routine maintenance, bounded coding and tests, Gemini high for deep implementation, and Luna max for deep investigation, documentation review and architecture review. The Haiku slot map uses medium for triage, high for standard/routine/test/docs and xhigh for deep/architecture review. Claude auto-routing narrows to its Haiku facet; ZCode auto-routing narrows to GLM/max. ZCode Apply reads the account-bound model selector from the existing host-owned `~/.zcode/agents/glm-max.md` and writes only marked `skills-manager-<slot>.md` agents through the backup/receipt/hash-checked transaction; it leaves the source agent, workflow and concurrency unchanged. The selected model ID remains in host configuration and never enters repository presets. DeepSeek and Terra are removed. `default_preset=gpt6_luna_only` selects the Codex root and fallback defaults; it does not restrict dispatch to one model. `AvailablePreset` narrows the whole pool; omitted means all four presets (six tuples) on Codex. DeepSeek, Terra and Sol presets are rejected; no preset aliases remain. Schema v6 `fallbacks` declares every slot's overload alternates explicitly (at most three exact tuples, output-only, never auto-executed; see README).
- Launcher-only dispatch for non-GPT slots (decided 2026-10-18): `quick_triage` (Haiku), `routine_maintenance`, `bounded_implementation` and `test_execution` (GLM), `standard_review` (Haiku) and `deep_implementation` (Gemini) must be dispatched through `Start-ModelSlot.ps1` (`codex exec`), never as a native subagent, because the native payload limit in README applies to those tuples. `deep_investigation`, `documentation_review` and `architecture_review` use `gpt-6-luna/max` and may use native dispatch.
- `Set-ModelPreset.ps1` enforces a code-level closed host allowlist: Codex accepts Luna/max, GLM/xhigh, Haiku/medium|high|xhigh and Gemini catalog slug `gemini-3.8-flash-high`/high; Claude accepts Haiku/medium|high|xhigh; ZCode accepts GLM/max. Editing `presets.json` cannot add a model or effort or cross host facets. The Gemini slug is the native ID; bare `gemini-3.8-flash` is not a supported alias.
- Native Codex subagents: only the GPT-family tuple (`gpt-6-luna` max) has been observed to read its task payload (2026-10-18). Non-GPT role tuples are marked direct-only in their role descriptions and the parent guidance; use `Start-ModelSlot.ps1` for them. See README "Native subagent payload limit".
- Semantic slots are extensible through `slots`, `read_only_slots` and each menu's `slot_map`, without a fixed count. Host-specific menu overrides live under `host_menus` and are validated independently. Nine semantic slots and six exact Codex tuple roles coexist; `deep_investigation` is read-only and `deep_implementation` is write-capable, replacing the previous mixed slot. `auto_routes` deterministically maps task shape to a preset for the selected host; an explicit `-Preset` pins one preset for all slots. Every slot may use any supported tuple from the active host pool, including different models on simultaneous tasks; slot names, task count and native concurrency are separate.
- The codex facet projects a native profile and shared root/agent defaults; Claude Code projects its supported settings and Haiku agent definitions; ZCode projects only per-slot GLM/max definitions derived from the host-owned model selector. For a subagent-only request use `-SubagentsOnly`: update roles and subagent defaults while preserving parent/review selections. ZCode Plan/Apply requires the existing host `glm-max.md` source and refuses unmarked target collisions. Slot-map shape violations fail closed at load.
- Ordinary host AI may classify and split tasks before dispatch. Delegation requires explicit authorization; parallel tasks require independent proof, disjoint write sets and positive benefit within native limits. Complexity re-selection applies before a new bounded task: concrete lookup -> quick, ordinary scoped work -> standard, unresolved cross-module/architecture/security constraints -> deep. Return to lighter work after uncertainty is resolved; do not replay completed writes.
- Check the current execution surface supports the exact tuple before spawning. The strict Codex launcher performs a native catalog preflight and blocks unsupported tuples before any model request; a relay/provider override is an explicit one-shot mode that requires a current, unexpired receipt bound to the exact model/effort, provider or surface, observed/expires timestamps and source. For Codex CLI it also resolves the effective named custom provider from the selected profile then base config, applies `request_max_retries=0` and `stream_max_retries=0` as per-invocation overrides, and blocks built-in or unresolved providers before dispatch. This caps Codex CLI retries only; downstream relay/provider retries remain outside this tool. Other hosts keep their own retry controls and must not inherit this claim. The eligible set is the declared host pool intersected with host-supported tuples. Missing input, auth/provider/tool failures, risk responses and 429 are not effort escalation signals. The launcher never replays a prompt or starts duplicate parallel requests. Availability re-selection is rule-projected, not automatic: 429/quota/rate-limit/auth/risk stops for operator or fresh parent selection; confirmed overload/unavailable permits at most one explicit reselection when the alternate tuple is supported. The launcher emits a structured `slot_failure` document with failure class and remaining reselection budget; free-text timeout mentions remain `unknown`; never silently alias model names, substitute an unsupported effort, hot-swap a running task or replay writes.
- Native projections preserve unrelated host configuration and retire orphan role tables only when config_file points into the generated Codex directory owned by this tool. Backups and receipts belong in ignored `.state/`; generated role files belong in `.generated/`.
- Verify: `pwsh -NoProfile -File Test-ModelPreset.ps1`, followed by the affected host's fresh config and request checks.
- Rollback: `Set-ModelPreset.ps1 -Action Rollback -ReceiptPath <receipt>`. Restore later dependent mutations first; hash drift must block rollback.
- Codex specialized delegation can bypass native hooks. Do not claim hard isolation from hook trust, unit tests, or ordinary config load.
- ZCode's native `model`/`thoughtLevel` file interface is verified from official docs; host loading and natural dispatch remain unverified until a fresh ZCode run. Antigravity still lacks a verified exact-model/effort adapter.
