# Model Orchestration

- Source: `presets.json`, `Set-ModelPreset.ps1`, `Start-ModelSlot.ps1`.
- Strict entrypoint: `Start-ModelSlot.ps1`; freeze one route and disable native delegation. Do not substitute a profile-only launch as strict acceptance.
- Runtime: PowerShell 7; no gateway selection, credential changes, daemon, or task replay.
- `presets.json` schema v4 jointly activates GPT-6-luna (`gpt-6-luna`) max, GLM-5.3-Flash max and DeepSeek V4.1-Flash max (exact slug `deepseek-v4.1-flash`); luna carries a codex facet only. Terra is removed. `default_preset=glm53_flash_only` selects fallback defaults; it does not restrict dispatch to one model. `AvailablePreset` narrows the whole pool; omitted means all three. Terra and Sol presets are rejected; no preset aliases remain.
- Semantic slots are extensible through `slots`, `read_only_slots` and each menu's `slot_map`, without a fixed count. Eight initial semantic slots and three exact tuple roles coexist. `auto_routes` deterministically maps task shape to a preset for the default route; an explicit `-Preset` pins one preset for all slots. Every slot may use any supported tuple from the active pool, including different models on simultaneous tasks; slot names, task count and native concurrency are separate.
- The codex facet projects a native profile and shared root/agent defaults. For a subagent-only request use `-SubagentsOnly`: update roles and subagent defaults while preserving parent/review selections. The launcher uses the first declared facet with a verified native interface; a `zcode` facet stays resolve-only. Slot-map shape violations fail closed at load.
- Ordinary host AI may classify and split tasks before dispatch. Delegation requires explicit authorization; parallel tasks require independent proof, disjoint write sets and positive benefit within native limits. Complexity re-selection applies before a new bounded task: concrete lookup -> quick, ordinary scoped work -> standard, unresolved cross-module/architecture/security constraints -> deep. Return to lighter work after uncertainty is resolved; do not replay completed writes.
- Check the current execution surface supports the exact tuple before spawning. The strict Codex launcher performs a native catalog preflight and blocks unsupported tuples before any model request; a relay/provider override is an explicit one-shot mode that requires a current, unexpired receipt bound to the exact model/effort, provider or surface, observed/expires timestamps and source. The eligible set is the declared pool intersected with host-supported tuples. Missing input, auth/provider/tool failures, risk responses and 429 are not effort escalation signals. Each bounded task has one upstream attempt: no duplicate prompt replay, duplicate parallel request or automatic retry. Availability re-selection is rule-projected, not automatic: 429/quota/rate-limit/auth/risk stops for operator or fresh parent selection; confirmed overload/unavailable permits at most one explicit reselection when the alternate tuple is supported. The launcher emits a structured `slot_failure` document with failure class and remaining reselection budget; free-text timeout mentions remain `unknown`; never silently alias model names, substitute max with xhigh, hot-swap a running task or replay writes.
- Native projections preserve unrelated host configuration and retire orphan role tables only when config_file points into the generated Codex directory owned by this tool. Backups and receipts belong in ignored `.state/`; generated role files belong in `.generated/`.
- Verify: `pwsh -NoProfile -File Test-ModelPreset.ps1`, followed by the affected host's fresh config and request checks.
- Rollback: `Set-ModelPreset.ps1 -Action Rollback -ReceiptPath <receipt>`. Restore later dependent mutations first; hash drift must block rollback.
- Codex specialized delegation can bypass native hooks. Do not claim hard isolation from hook trust, unit tests, or ordinary config load.
- ZCode projection remains blocked until its native model/effort write interface is verified.
