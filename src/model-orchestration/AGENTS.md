# Model Orchestration

- Source: `presets.json`, `Set-ModelPreset.ps1`, `Start-ModelSlot.ps1`.
- Strict entrypoint: `Start-ModelSlot.ps1`; freeze one route and disable native delegation. Do not substitute a profile-only launch as strict acceptance.
- Runtime: PowerShell 7; no gateway selection, credential changes, daemon, or task replay.
- `presets.json` schema v4 jointly activates GPT-6.1-Sol medium/low, GPT-6-luna max and GLM-5.3-Flash max/high. DeepSeek is removed. `default_preset=gpt61_sol_only` selects fallback defaults; it does not restrict dispatch to one model. `AvailablePreset` narrows the whole pool; omitted means all three. Legacy GPT preset arguments resolve to canonical IDs.
- Semantic slots are extensible through `slots`, `read_only_slots` and each menu's `slot_map`, without a fixed count. Eight initial semantic slots and six exact tuple roles coexist. Every slot may use any supported tuple from the active pool, including different models on simultaneous tasks; slot names, task count and native concurrency are separate.
- The codex facet projects a native profile and shared root/agent defaults. For a subagent-only request use `-SubagentsOnly`: update roles and subagent defaults while preserving parent/review selections. The launcher uses the first declared facet with a verified native interface; a `zcode` facet stays resolve-only. Slot-map shape violations fail closed at load.
- Ordinary host AI may classify and split tasks before dispatch. Delegation requires explicit authorization; parallel tasks require independent proof, disjoint write sets and positive benefit within native limits. Complexity re-selection applies before a new bounded task: concrete lookup -> quick, ordinary scoped work -> standard, unresolved cross-module/architecture/security constraints -> deep. Return to lighter work after uncertainty is resolved; do not replay completed writes.
- Check the current execution surface supports the exact tuple before spawning. The eligible set is the declared pool intersected with host-supported tuples. Missing input, auth/provider/tool failures and 429 are not effort escalation signals. Availability re-selection is rule-projected, not automatic: Apply writes the deterministic chain (429/quota/auth -> nearest lower effort, then next active preset; confirmed overload/unavailable -> also nearest higher effort) into profile instructions and the `# availability-rules:` config block, and the launcher emits a structured `slot_failure` document on failure. The parent re-selects another supported tuple for the next bounded task, preserving proof and recording the reason; never silently alias model names, substitute max with xhigh, hot-swap a running task or replay writes.
- Native projections preserve unrelated host configuration. Backups and receipts belong in ignored `.state/`; generated role files belong in `.generated/`.
- Verify: `pwsh -NoProfile -File Test-ModelPreset.ps1`, followed by the affected host's fresh config and request checks.
- Rollback: `Set-ModelPreset.ps1 -Action Rollback -ReceiptPath <receipt>`. Restore later dependent mutations first; hash drift must block rollback.
- Codex specialized delegation can bypass native hooks. Do not claim hard isolation from hook trust, unit tests, or ordinary config load.
- ZCode projection remains blocked until its native model/effort write interface is verified.
