# Model Orchestration

- Source: `presets.json`, `Set-ModelPreset.ps1`, `Start-ModelSlot.ps1`.
- Native Codex routing uses the named `[agents.*]` slot/tuple roles generated from the strict allowlist. `Start-ModelSlot.ps1` is a separate explicitly invoked one-shot CLI path; its plan or receipt does not prove native subagent execution.
- Runtime: PowerShell 7; no gateway selection, credential changes, daemon, or task replay.
- Schema v7 keeps the strict Codex pool: Luna/max, GLM/xhigh, Haiku/medium|high|xhigh, and Gemini catalog slug `gemini-3.8-flash-high`/high. All six tuples are projected as native tuple roles after current `codex debug models` preflight. Auto routes use Haiku medium for quick triage, Haiku high for standard review, GLM xhigh for routine maintenance, bounded coding and tests, Gemini high for deep implementation, and Luna max for deep investigation, documentation and architecture review. Claude narrows to Haiku; ZCode narrows to GLM/max. `default_preset=gpt6_luna_only` selects the Codex parent root and does not disable automatic routing across all four families. `AvailablePreset` narrows the native route pool; omitted means all six exact tuples. Schema v7 declares exact per-slot fallbacks and a parent budget for controlled launcher invocations.
- Codex named task slots and tuple roles pin their exact model/effort. `Start-ModelSlot.ps1` (`codex exec`) remains an explicit direct CLI path and is not substituted for native subagent dispatch. The historical Luna/Haiku/Gemini/GLM task-payload probe only established that its own payload-read test failed for three children; the user has confirmed prior successful ChatGPT Desktop use of all four model families, so probe-task failure is not treated as a model capability gate.
- `Set-ModelPreset.ps1` enforces a code-level closed host allowlist: Codex accepts Luna/max, GLM/xhigh, Haiku/medium|high|xhigh and Gemini catalog slug `gemini-3.8-flash-high`/high; Claude accepts Haiku/medium|high|xhigh; ZCode accepts GLM/max. Editing `presets.json` cannot add a model or effort or cross host facets. The Gemini slug is the native ID; bare `gemini-3.8-flash` is not a supported alias.
- Native Codex task-payload probe results are historical diagnostics, not capability evidence: Haiku reported unreadable encrypted content, and the Gemini/GLM children did not return the assigned reply. The exact envelope cause remains outside this repository. Current native support is preflighted against the model catalog and closed six-tuple allowlist; actual host load and successful task dispatch remain separate evidence layers.
- Semantic slots are extensible through `slots`, `read_only_slots` and each menu's `slot_map`. Nine semantic slots and six exact native Codex tuple routes coexist. `auto_routes` maps task shape for the selected host; `-Preset` pins controlled slot routes. Each bounded task supplies a concrete scope, write set, proof and stop.
- The codex facet projects a native profile and shared root/agent defaults; Claude Code projects its supported settings and Haiku agent definitions; ZCode projects only per-slot GLM/max definitions derived from the host-owned model selector. For a subagent-only request use `-SubagentsOnly`: update roles and subagent defaults while preserving parent/review selections. ZCode Plan/Apply requires the existing host `glm-max.md` source and refuses unmarked target collisions. Slot-map shape violations fail closed at load.
- Ordinary host AI may classify and split tasks before dispatch. Delegation requires explicit authorization; parallel tasks require independent proof, disjoint write sets and positive benefit within native limits. Complexity re-selection applies before a new bounded task: concrete lookup -> quick, ordinary scoped work -> standard, unresolved cross-module/architecture/security constraints -> deep. Return to lighter work after uncertainty is resolved; do not replay completed writes.
- Check exact tuple support before dispatch. The strict Codex launcher preflights the native catalog and blocks unsupported tuples. Provider-override evidence must be current, unexpired and bind exact model/effort, `provider_id`, surface, timestamps and source; the ID must match the effective provider resolved from profile/base config. Every execution mode requires a declared custom provider and applies Codex CLI request/stream retry caps per invocation. This controls CLI retries, not internal model requests or downstream relay retries. The launcher makes one `codex exec` call and never automatically retries or replays; the parent tracks task-level launch/reselection counts. Auth, provider, tool, risk and 429 failures are not effort-escalation signals; preserve fail-closed handling and no silent aliases or substitutions.
- Native projections preserve unrelated host configuration and retire orphan role tables only when config_file points into the generated Codex directory owned by this tool. Backups and receipts belong in ignored `.state/`; generated role files belong in `.generated/`.
- Verify: `pwsh -NoProfile -File Test-ModelPreset.ps1`, followed by the affected host's fresh config and request checks.
- Rollback: `Set-ModelPreset.ps1 -Action Rollback -ReceiptPath <receipt>`. Restore later dependent mutations first; hash drift must block rollback.
- Codex specialized delegation can bypass native hooks. Do not claim hard isolation from hook trust, unit tests, or ordinary config load.
- ZCode's native `model`/`thoughtLevel` file interface is verified from official docs; host loading and natural dispatch remain unverified until a fresh ZCode run. Antigravity still lacks a verified exact-model/effort adapter.
