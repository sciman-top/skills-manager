# Model Orchestration

- Source: `presets.json`, `Set-ModelPreset.ps1`, `Start-ModelSlot.ps1`.
- Native Codex routing uses the named `[agents.*]` slot/tuple roles generated from the strict allowlist. Native roles must be GPT-family (`native_subagent` presets); GLM/Gemini remain launcher-only because the gateway rejects opaque `agent_message.encrypted_content` on those routes with 422 before contacting upstream. `Start-ModelSlot.ps1` is a separate explicitly invoked one-shot CLI path; its plan or receipt does not prove native subagent execution.
- Runtime: PowerShell 7; no gateway selection, credential changes, daemon, or task replay.
- Schema v7 keeps the strict Codex pool: Luna/max, GLM/xhigh, and Gemini catalog slug `gemini-3.8-flash-high`/high. All three tuples are projected as native tuple roles after current `codex debug models` preflight. Auto routes use Gemini high for quick triage, standard review and deep implementation, GLM xhigh for routine maintenance, bounded coding and tests, and Luna max for deep investigation, documentation and architecture review. ZCode narrows to GLM/max. The Claude family was retired from the pool (2026-10-20 user decision); the Claude host facet has no active preset and fails closed. `default_preset=gpt6_luna_only` selects the Codex parent root and does not disable automatic routing across all three families. `AvailablePreset` narrows the native route pool; omitted means all three exact tuples. Schema v7 declares exact per-slot fallbacks and a parent budget for controlled launcher invocations.
- Codex named task slots and tuple roles pin their exact model/effort. `Start-ModelSlot.ps1` (`codex exec`) remains an explicit direct CLI path and is not substituted for native subagent dispatch. The 2026-10-22 root cause is host-side: `cpa-admission.py` returns 422 `encrypted_agent_payload_unsupported` for `claude-`/`glm-`/`gemini-` routes before any upstream request, so those families cannot back a native subagent even though they work as `codex exec` one-shot children.
- `Set-ModelPreset.ps1` enforces a code-level closed host allowlist: Codex accepts Luna/max, GLM/xhigh and Gemini catalog slug `gemini-3.8-flash-high`/high; ZCode accepts GLM/max. Editing `presets.json` cannot add a model or effort or cross host facets. The Gemini slug is the native ID; bare `gemini-3.8-flash` is not a supported alias.
- Native Codex task-payload probe results are historical diagnostics, not capability evidence. The envelope cause is now identified at the gateway admission layer, not in this repository: non-GPT native routes are rejected by request shape. Native role exposure is preflighted against the model catalog and the GPT-only native allowlist; actual host load and successful task dispatch remain separate evidence layers. `Set-ModelPreset.ps1 -Action Verify` is a read-only preflight for the current host config.
- Semantic slots are extensible through `slots`, `read_only_slots` and each menu's `slot_map`. Nine semantic slots and three exact native Codex tuple routes coexist. `auto_routes` maps task shape for the selected host; `-Preset` pins controlled slot routes. Each bounded task supplies a concrete scope, write set, proof and stop.
- The codex facet projects a native profile and shared root/agent defaults; ZCode projects only per-slot GLM/max definitions derived from the host-owned model selector. For a subagent-only request use `-SubagentsOnly`: update roles and subagent defaults while preserving parent/review selections. ZCode Plan/Apply requires the existing host `glm-max.md` source and refuses unmarked target collisions. Slot-map shape violations fail closed at load.
- Ordinary host AI may classify and split tasks before dispatch. Delegation requires explicit authorization; parallel tasks require independent proof, disjoint write sets and positive benefit within native limits. Complexity re-selection applies before a new bounded task: concrete lookup -> quick, ordinary scoped work -> standard, unresolved cross-module/architecture/security constraints -> deep. Return to lighter work after uncertainty is resolved; do not replay completed writes.
- Check exact tuple support before dispatch. The strict Codex launcher preflights the native catalog and blocks unsupported tuples. Provider-override evidence must be current, unexpired and bind exact model/effort, `provider_id`, surface, timestamps and source; the ID must match the effective provider resolved from profile/base config. Every execution mode requires a declared custom provider and applies Codex CLI request/stream retry caps per invocation. This controls CLI retries, not internal model requests or downstream relay retries. The launcher makes one `codex exec` call and never automatically retries or replays; the parent tracks task-level launch/reselection counts. Auth, provider, tool, risk and 429 failures are not effort-escalation signals; preserve fail-closed handling and no silent aliases or substitutions.
- Native projections preserve unrelated host configuration and retire orphan role tables only when config_file points into the generated Codex directory owned by this tool. Backups and receipts belong in ignored `.state/`; generated role files belong in `.generated/`.
- Verify: `pwsh -NoProfile -File Test-ModelPreset.ps1`, followed by the affected host's fresh config and request checks.
- Rollback: `Set-ModelPreset.ps1 -Action Rollback -ReceiptPath <receipt>`. Restore later dependent mutations first; hash drift must block rollback.
- Codex specialized delegation can bypass native hooks. Do not claim hard isolation from hook trust, unit tests, or ordinary config load.
- ZCode's native `model`/`thoughtLevel` file interface is verified from official docs; host loading and natural dispatch remain unverified until a fresh ZCode run. Antigravity still lacks a verified exact-model/effort adapter.
