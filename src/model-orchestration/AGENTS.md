# Model Orchestration

- Source: `presets.json`, `Set-ModelPreset.ps1`, `Start-ModelSlot.ps1`; independent of the main CLI build. PowerShell 7 only. No credentials, provider changes, gateway deployment or host process management.
- The active Codex pool is Luna/max, GLM-5.3-Flash/xhigh, and Gemini catalog slug `gemini-3.8-flash-high`/high. DeepSeek V4.1-Flash is excluded from presets, routes, allowlists and fallback candidates. ZCode's separately reviewed GLM facet remains max. Effort names are host-specific, not a cross-model strength scale; product-level provider support does not imply a writer in this repository.
- Native roles expose the three approved Codex tuples after target-catalog preflight. The BWG admission deployment from 2026-10-25 maps only the exact known Codex task envelope to standard Responses user text before forwarding; unknown envelope shapes remain rejected. Catalog visibility and deployment loading do not prove a child completed useful work. Stop on `encrypted_agent_payload_unsupported`; do not bypass the guard or replay.
- Nine semantic slots describe task responsibility. Read-only slots: quick triage, standard review, deep investigation, documentation review, architecture review. Implementation requires explicit scope, write set, proof and stop. Native role files pin model and effort and may override spawn arguments; launcher routes are separate.
- Codex defaults: Luna/max for quick triage and documentation review; GLM/xhigh for routine maintenance, bounded implementation and test execution; Gemini/high for standard review, deep investigation, deep implementation and architecture review. These are task-fit hypotheses, not measured rankings; see README for rationale and host evidence.
- `presets.json.routing_receipt` is the v1 observability contract: record requested slot/preset/model/effort/read-only/fallback data separately from host-reported actual model/effort; use `actual_model_observed=false` when the host does not expose the child tuple.
- Defaults and alternates are policy choices, not a universal model ranking. The historical small evaluation does not validate long-horizon native tasks. Use ordinary accepted outcomes to refine concrete mismatches; do not issue a broad model sweep.
- One primary executor; delegate only authorized independent bounded slices with disjoint write sets, independent proof and positive benefit. Keep coupled writes serial and respect the shared host concurrency limit.
- Schema v7 defines ordered per-slot manual reselection candidates and a parent-managed dispatch budget; candidates never auto-run. The launcher makes one `codex exec` call, with no automatic retry or replay. Only structured upstream-unavailable/overload permits one explicit parent reselection for reviewed remaining scope. 429/quota, auth, risk, tool, timeout and compatibility failures are not model-switch signals; respect cooldown/reset and inspect partial writes. Other hosts may retry a request or route `Auto` traffic under their own versioned rules; see README and do not infer child-agent failover.
- Apply defaults to `-SubagentsOnly`. Full-scope Apply also rewrites parent-root scalars (`model`, `review_model`, `model_reasoning_effort`, `model_verbosity`); those scalars and the host model catalog are operator-owned (host config tools manage them), so projection work reports their drift and never auto-restores without explicit operator instruction for the current task. Plan before Apply; generated files are in ignored `.generated/`, receipts/backups in ignored `.state/`. Preserve unrelated host config. Do not publish backups. ZCode requires its existing host-owned `glm-max.md`; unmarked target collisions fail closed. No verified WorkBuddy CN/INTL, DeepSeek Harness or Antigravity model-preset writer or child-agent adapter; Claude has no active facet.
- Live projection probes bind the target `CODEX_HOME`. Catalog snapshots require source, absolute target root and a current validity window of at most five minutes. Provider overrides require current exact-tuple evidence binding the effective provider. Every controlled execution requires a declared custom provider and zero CLI request/stream retry caps, which do not control relay retries.
- Verify: `pwsh -NoProfile -File Test-ModelPreset.ps1`; then Plan/Apply/Verify and a fresh host load as applicable. Tests and catalog checks do not establish live generation or hard isolation. Native tools can bypass hooks; child permissions follow the parent. Do not restart the host to force loading.
- Rollback: `Set-ModelPreset.ps1 -Action Rollback -ReceiptPath <receipt>`; restore later dependent mutations first and stop on hash drift.
- Stop at the requested evidence boundary. Keep `repo_verified`, `filesystem_projected`, `host_loaded`, `live_accepted` separate. See README for launcher timeouts, failure classification and host boundaries.
