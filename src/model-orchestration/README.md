# Model Presets

This independent PowerShell 7 tool projects the joint model pool defined in `presets.json` (schema v6). It does not select gateways, inspect credentials, retry tasks or run background monitors.

Four model families are in the ChatGPT Desktop/Codex subagent pool: GPT-6 Luna at `max`, GLM-5.3-Flash at `xhigh`, Claude Haiku 5.5 at `medium`, `high` and `xhigh`, and Gemini 3.8 Flash at `high` (relay catalog slug `gemini-3.8-flash-high`). The task routes use Haiku medium for quick triage, Haiku high for standard review, GLM xhigh for routine maintenance, bounded implementation and test execution, Gemini high for deep implementation, and Luna max for deep investigation, documentation review and architecture review. These defaults come from a real-API evaluation (2026-10-18, allowlisted tuples only), not from vendor positioning alone. The Haiku preset maps triage to `medium`, standard, routine, test and document review to `high`, and deep/architecture review to `xhigh`. Other hosts stay within their own native model families: Claude Code routes only Haiku, ZCode only GLM/max, and Antigravity remains on its `inherit`/`flash`/`pro` tiers because it cannot express these exact model/effort tuples. No Codex model or effort is projected to those hosts. DeepSeek and Terra are removed. Each child task may use an exact supported tuple from its host pool, and different tasks may use different models. `default_preset=gpt6_luna_only` remains the default preset; `-SubagentsOnly` preserves the parent model and review selection when projecting subagents. Menu order is per-model effort, not a cross-model performance ranking.

The executable enforces a closed, host-specific tuple allowlist, so adding a preset or changing `presets.json` cannot expand it: Codex allows `gpt-6-luna/max`, `glm-5.3-flash/xhigh`, `claude-haiku-5-5/medium|high|xhigh` and the native Gemini catalog ID `gemini-3.8-flash-high/high`; Claude Code allows only the three Haiku tuples; ZCode allows only `glm-5.3-flash/max`. The native Codex catalog uses `gemini-3.8-flash-high` as the model ID for Gemini 3.8 Flash at high effort; the bare product-family string `gemini-3.8-flash` is not an accepted alias.

No legacy preset aliases remain. DeepSeek, Terra and Sol presets and aliases are rejected; the subagent pool excludes them without changing the parent model. `-Preset` pins one preset for all slots; without it, `auto_routes` selects the task-shape tuple. `-AvailablePreset` limits the jointly enabled pool; if an automatic route is excluded, the first remaining launchable preset is used and the `fallback_from` field records that decision. Resolve returns `active_presets`, `enabled_routes`, `slots`, `routes` and the dispatch policy. These are declared routes until the current execution surface passes capability preflight. Historical profile and custom role files remain outside the active managed block; launching an old profile directly does not invoke the current pool.

The nine semantic slots are `quick_triage`, `routine_maintenance`, `standard_review`, `bounded_implementation`, `deep_investigation`, `deep_implementation`, `test_execution`, `documentation_review` and `architecture_review`. They describe task scope, not a fixed child count or concurrency allocation. `deep_investigation` is read-only; `deep_implementation` requires a concrete scope and write set. The former `deep_investigation_or_implementation` slot has been split to prevent open-ended investigation from implicitly carrying write permission; callers should choose the new slot matching the task. Extend `slots` and every menu's `slot_map` together; include read-only additions in `read_only_slots`. The launcher validates these fields dynamically. Each configured slot can select any pool tuple using `-Model` and `-Effort` together.

Five exact tuple roles coexist in the ordinary Codex host alongside `luna_max`: `glm_xhigh`, `haiku_medium`, `haiku_high`, `haiku_xhigh` and `gemini_high`. The parent selects a tuple role and supplies the semantic slot, scope, write set, proof and stop in its assignment. Semantic roles retain fallback routes and read-only descriptions. A fixed custom role's model/effort cannot be overridden: choose the matching tuple role or a supported native explicit tuple route instead. Specialist bridges retain their own execution contracts.

Native subagent payload limit (2026-10-18 read-only probes): on Codex, a native child receives its task as an `encrypted_content` envelope. Only the `gpt-6-luna` tuple read it. `claude-haiku-5-5` reported an unreadable Fernet token, while `gemini-3.8-flash-high` and `glm-5.3-flash` did not reply. Routing and effort were correct in every case, so the failure is in reading the payload. Until a native probe passes for a tuple, only the GPT-family tuple is a native subagent target on Codex. Non-GPT tuples must be dispatched through `Start-ModelSlot.ps1` (`codex exec`), which passed one minimal request for each tuple. The cause is not established in this repository.

Menus must contain one model in strictly increasing effort order: failure re-selection interprets earlier entries as lower effort. Resolve rejects reversed or mixed-model menus. The Codex menus are single-tier except haiku (medium < high < xhigh): a failed haiku/xhigh can downgrade within the preset to high then medium before any cross-preset move, while luna, GLM and Gemini stay single-tier with no within-model downgrade. The ZCode GLM facet is a separate single-tier max menu.

An ordinary host AI can classify a task, split its dependencies and choose the deterministic slot route before dispatch. Delegate only when the user or applicable instructions explicitly authorize delegation. Parallel dispatch additionally needs independently verifiable slices, disjoint write sets, positive benefit and the host's native concurrency budget. These presets provide a deterministic slot route; they do not install a background scheduler or grant delegation permission.

- Choose `quick_triage` for a small read-only lookup, known error classification or concrete evidence check.
- Choose `routine_maintenance` for a small, well-understood fix; `bounded_implementation` for a specified change with explicit write set and proof; `standard_review` for read-only review; and `test_execution` for a scoped test command and failure diagnosis. `documentation_review` checks written contracts and `architecture_review` checks interacting constraints or security boundaries.
- Choose `deep_investigation` for unresolved cross-module behavior, root cause, architecture or security questions. It is read-only and returns evidence plus a proposed bounded change. Use `deep_implementation` for the resulting complex change only after scope and write set are explicit.
- Choose the model independently by task fit: vendor descriptions position Luna for efficient focused work, Haiku for latency-sensitive classification/routing/subagent work, Gemini Flash for long-horizon software engineering and autonomous agents, and GLM for coding. These statements do not establish a shared ranking, actual latency, cost on the selected endpoint or task accuracy. The Codex route table uses the exact supported tuples below; Claude Code narrows to Haiku and ZCode to GLM/max. Antigravity's tier-only menu cannot express these exact tuples. If a child returns unresolved uncertainty, the parent reviews its evidence and remaining scope before re-selection; completed writes are not replayed.
- Return to a smaller scope for the next independent task once the remaining question is concrete. Only haiku carries within-model effort rungs; the other models are single-tier. Choose the model independently by task fit and current support; there is no measured universal ranking between these models.
- Missing input requires clarification. Authentication, provider, tool and 429 failures require their own diagnosis; they do not justify increasing effort or blindly repeating a task.

When a tuple is unavailable, the parent may choose another supported pool tuple for the remaining or next bounded task and record the reason. Whole-preset switching is not required. Preserve scope, proof and prior work; do not replay completed writes or silently substitute effort. A runtime failure is not itself evidence that another model is entitled or that higher effort will fix it.

Schema v6 declares each slot's overload alternates explicitly in `presets.json` under `fallbacks`: an ordered list of at most three exact tuples, each naming `preset`, `model` and `effort`. An empty list is an explicit "no automatic alternate". Load fails closed when a slot is missing, a tuple is not in its preset's menu, an entry repeats the slot's own route or another entry, or `schema_version` is not 6. Resolve returns each route's `declared_fallback`, restricted to the active host pool with the route's own tuple removed. `Start-ModelSlot.ps1` reports the same list in `-Plan` and, after a confirmed overload, as `slot_failure.reselection.declared_fallback` with the launched tuple removed; this replaces the v5 implicit `cross_preset` list. The parent takes the first alternate it can currently support, once. Alternates are output only: the launcher never replays, retries or starts a second request, and 429, quota, auth and risk failures still stop for fresh selection. `within_preset_lower` continues to report the failed model's menu ladder.

A confirmed availability failure is recorded for the current task; the parent may choose a supported tuple for the next bounded task using the declared pool order that Apply projects into the profile instructions and the shared config block (`# availability-rules:`). Each bounded task gets one launcher invocation. The launcher never replays an identical prompt, sends duplicate parallel requests or retries automatically. For 429/quota/rate-limit/auth/risk responses, stop and wait for operator or fresh parent selection. A confirmed overload/unavailable response permits at most one explicit reselection, only when the alternate tuple is currently supported. The launcher prints a structured `slot_failure` document with the failure class, capability status, upstream-contact flag and remaining reselection budget. Record the failed tuple, failure, selected tuple and remaining scope. Inspect any partial writes before continuation; a failed read-only request is a new bounded task only after parent review. Each child launch remains frozen. Higher effort under overload is an availability choice only when that tuple is supported; it does not establish that rate limiting was caused by insufficient reasoning.

This one-attempt policy covers the controlled launcher and its parent-mediated route. Ordinary native ChatGPT Work, Claude Code/Desktop, ZCode and Antigravity sessions remain host-owned surfaces; their retry, replay and concurrency behavior must be checked separately and must not be reported as governed by this tool. A host-native workflow is accepted only after its own current lifecycle and failure evidence is available.

Codex custom-agent files cannot override the parent session's sandbox or approval settings, and `[agents].enabled` is a root config setting rather than a per-agent switch. Bridge templates therefore carry workflow instructions only: `Never spawn subagents` is not a hard tool restriction. A read-only child requires a read-only parent session; one-shot parent dispatch must also verify that no nested child was spawned.

The strict launcher performs a native Codex capability preflight before contacting the model. Eligible native tuples are the declared Codex pool intersected with the current catalog's exact model and reasoning levels. `AvailablePreset` and offline Resolve describe routes, not entitlements. A model entry alone does not establish support for every configured effort. If a relay/provider override is required, pass `-CapabilityMode provider_override -CapabilityProbePath <receipt.json>` for one explicit bounded request. The receipt must contain a verified exact tuple plus `surface` (or `provider`), `observed_at`, `expires_at` and `source`; it is rejected when missing, malformed or expired. A static MOR-090 row alone is not current temporal evidence. This mode does not retry or upgrade the tuple. Retain unsupported tuples as configuration only. Do not infer aliases from display names or silently replace a selected effort. Catalog observations do not establish provider request success.

Failure classification consumes structured JSON error fields (`code`, `reason_code`, `category`, `type`, `status` or `http_status`) only. Free text, including a model message that merely mentions `timeout`, remains `unknown` and stops for diagnosis; the launcher never guesses an upstream outage from prompt or log text.
