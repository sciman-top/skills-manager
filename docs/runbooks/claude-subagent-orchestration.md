# Claude 原生子代理与本项目边界

**状态**: 能力边界说明；能力随宿主版本变化，派发前以当前帮助、schema 和实际支持面为准。
**适用**: Claude Code 宿主（Desktop Code tab 与 CLI）。
**边界**: 本手册不写 `~/.claude`，也不声称宿主已加载某个代理或使用某个模型。

## 1. 职责划分

- 子代理类型、继承关系、模型、effort、并发、上下文和工具权限，由 Claude Code 及其用户配置决定。
- `skills-manager` 只提供技能内容、发现 catalog、依赖闭包校验和显式投影；它不生成子代理定义，也不接管子代理编排。
- 本机模型选择、环境变量或一次调用的结果都不证明其他宿主采用相同默认值。

## 2. 何时派发

- 沿用宿主与项目已有的委派授权；只有切片独立、写集互斥、最低证明和停止条件都明确时才派发。
- 简单任务留在父对话；访谈、单轮实现和需要连续用户决定的任务，不要求套用仓库预设的代理或模型。
- 失败时保留原始错误并按宿主规则处理；不靠未经授权的自动重试、换模型或换凭据绕过失败。

## 3. 证据与未验证项

- 声称“已派发”或“使用了某个模型”，须有当前宿主事件；子代理自述或文件存在不能替代宿主执行证据。
- 冷发现回执只能证明候选、入口文件和依赖闭包校验；child、模型、技能加载和用户结果须另行观测。
- 本文不固定模型档位、默认并发或自动重试；这些值以各宿主当前的官方配置与真实事件为准。
