## Process Defect Found And Repaired

初始 current-fact 审查发现：上一轮删除 `postgres` MCP server 后，`skills.json.mcp_profiles.profiles.database.enabled` 仍引用 `postgres`；active default profile 使原 `doctor --strict` 未暴露该悬空项，而切换 `database` 会失败。

根因：

- `Apply-AuditMcpSelections` 删除 server 时只更新 `mcp_servers`。
- 普通 `卸载MCP` 也没有统一清理 profile 引用。
- 配置契约只检查 `enabled` 是数组，不检查 `enabled` / `enabled_tools` 引用是否存在。

修复：

- 新增 `Remove-McpProfileServerReferences`，普通卸载与 audit apply 共用。
- 删除 server 时清理所有 profile 的 `enabled` 和 `enabled_tools` 引用，大小写不敏感。
- `Get-CfgContractErrors` 与 `Assert-Cfg` 检查所有 profile 的悬空引用，并对 null profile fail-closed。
- 当前 `database` profile 修正为空数组；未新增、启用或投影任何 MCP。
- 增加 audit apply E2E 与配置契约回归测试；重新生成 `skills.ps1`。
