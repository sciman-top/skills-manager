## 新增候选详细研究

### A1. Remotion 子技能独立登记

证据 1（本轮本地真值）：`installed-skills.json` 只记录一个 managed `remotion-best-practices`。本地 `skills.json` 将 `skills\\remotion-best-practices` 映射到 `skills-2-skills-remotion`，其目录内已经包含 `remotion-create`、`remotion-render`、`remotion-captions`、`remotion-interactivity`、`remotion-markup`、`remotion-saas` 和 `mediabunny` 的渐进披露入口。

证据 2（官方上游与供应链锁）：本轮 `git ls-remote https://github.com/remotion-dev/skills.git HEAD` 返回 `8b1d51ade295b2d9bd22a8f07047d13c0740f275`，与本地 `skills.lock.json` 和 vendor HEAD 一致。官方仓库的根 skill 本身负责路由到这些子技能，不需要把每个子目录重复登记为新的独立 skill。上游：[remotion-dev/skills](https://github.com/remotion-dev/skills)，具体锁定树：[commit 8b1d51a 的 remotion-best-practices](https://github.com/remotion-dev/skills/tree/8b1d51ade295b2d9bd22a8f07047d13c0740f275/skills/remotion-best-practices)。

维护与依赖：上游活跃；Remotion 使用 Node/npm、React、Chromium/媒体渲染链。Remotion 官方说明个人、非营利和不超过 3 人的营利组织可以使用免费许可，更大营利组织需要 company license；这属于使用 Remotion runtime 的成本边界，而不是 skill 文件本身的安装费用。[Remotion 官方许可](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)

结论：`do_not_install` as separate objects。保留一个 router/root skill，可降低触发竞争与常驻 metadata；只有当 skills-manager 将来正式支持“嵌套 skill 独立 inventory”并有 schema/路由迁移方案时再重评。

结论：不是新增项；`keep_disabled`。只在“无真实登录态要求、需要连续结构化 accessibility snapshot 的专项 Web 测试”中临时启用。

### A6. Upstash Context7 MCP

证据 1（本轮本地真值）：它已经是 repo-managed MCP，当前 `enabled=false`，命令为 `npx -y @upstash/context7-mcp`，工具为 `resolve-library-id` 与 `query-docs`。目标中的 Microsoft/OpenAI 官方资料已分别由 enabled 的 `microsoft-learn`、`openaiDeveloperDocs` 覆盖。

证据 2（官方隐私）：Context7 声明不会发送完整 prompt 或源码，但会发送 MCP 生成的 query、library name/id、API key、client/version、transport；query 会交给 OpenAI、Gemini、Anthropic 等 provider 做 reranking，并匿名存储用于 benchmark/质量改进，API logs 保留 30 天。Enterprise 才能关闭 benchmark query storage。[Context7 Data Privacy](https://context7.com/docs/security/data-privacy)

证据 3（官方依赖、额度与维护）：Node >=18，API key recommended；匿名/免费访问有额度限制，Pro 与私有源存在费用。仓库 MIT 且仍活跃，但开源 MCP client 不等于其检索后端开源或本地化。[upstash/context7](https://github.com/upstash/context7)，[Context7 Plans](https://context7.com/plans)，[Context7 Troubleshooting](https://context7.com/docs/resources/troubleshooting)。

结论：不是新增项；`keep_disabled`。仅在跨生态、版本特定官方资料缺口明确且 query 可完全去敏时按需启用，不应同时安装 Context7 plugin、CLI skill 和第二份 MCP。

## 卸载候选与保留理由

### R1. `powerpoint-automation`

潜在卸载理由是它与 `custom-teacher-courseware-ppt`、`pptx`、`baoyu-slide-deck`、plugin `Presentations` 都出现 PPT 关键词。但它们角色不同：

- `custom-teacher-courseware-ppt`：教学领域 workflow/router。
- `pptx` / plugin `Presentations`：文件级 executor。
- `baoyu-slide-deck`：图片化 deck executor。
- `powerpoint-automation`：Windows PowerPoint COM、打开中的 PowerPoint 与 overflow review operator/executor。

独立证据一是用户画像明确把 PPT/PPTX 课件列为第一类主工作流；独立证据二是 Microsoft 官方 PowerPoint object model 确实支持 presentations/slides 的打开、编辑、保存和导出。[PowerPoint Presentations object](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentations)

主要风险不是“技能无用”，而是运行环境：Microsoft 不支持无人值守、非交互式、服务端 Office automation，因为可能不稳定或死锁。[Microsoft 对 server-side Office automation 的说明](https://support.microsoft.com/en-us/topic/considerations-for-server-side-automation-of-office-48bcfe93-8a89-47f1-0bce-017433ad79e2)

裁决：保留；只在 Windows 交互桌面、已安装 PowerPoint、用户可见会话中触发，禁止把 COM 路径用于服务、计划任务 SYSTEM 会话或服务器端批处理。

### R2. 浏览器技能组

`playwright`、`webapp-testing`、`playwright-best-practices`、`agent-browser` 与 plugin browser skills 存在关键词重叠，但当前 repo scans 在 `classroom-answer-toolkit` 和 `qq-codex-bot` 检测到 Playwright，这是保留浏览器测试能力的独立目标证据。installed snapshot 的描述又表明它们分别是 CLI executor、local-web workflow、测试规范 reference/validator、通用 browser executor 和已登录 session operator。

裁决：保留，不做卸载；通过触发规则解决竞争，不同时争用同一 profile。

### R3. `windows-desktop-e2e`

独立证据一：`ClassroomToolkit` 与 `classroom-answer-toolkit` 都是 .NET/WPF 类目标；独立证据二：`windows-desktop-e2e` 是 pywinauto/UIA 的 validator，而 plugin `computer-use` 是当前会话的可见 operator。WinAppDriver 的维护和权限证据也不支持用新服务替代它。

裁决：保留；测试需在人工可见、可复位的桌面环境运行，避免与真实教学数据会话混用。

### R4. `ant-design`

`decision-insights.json` 给出 score 0，但这只是关键词匹配结果。另一个独立事实是 `k12-question-graph` 检测到 React/Vite；官方 Ant Design 当前支持现代浏览器、SSR、Electron 和 React，仍是活跃技术路线。[Ant Design 官方介绍](https://ant.design/docs/react/introduce/)

裁决：不卸载。当前没有证据证明目标使用 `antd`，也没有使用遥测证明它从未触发；在缺少 profile budget 压力和真实无用证据时，零分不足以形成 removal recommendation。

### R5. `supabase-postgres-best-practices`

`decision-insights.json` 给出 score 0，且 9 个目标扫描未发现 Supabase/Postgres，这是潜在卸载的两项本地信号。但官方 skill 仍有明确的 Postgres 查询、索引、连接池、RLS 与性能角色，仓库存在 release/test 治理并持续维护。[supabase/agent-skills](https://github.com/supabase/agent-skills)

裁决：不卸载。当前信号只能证明“本轮目标未命中”，不能证明长期无用；缺少使用遥测、触发日志和 profile budget 压力。若以后需要收缩，应先观察一个治理周期，再以零触发 + 无目标依赖 + 可恢复归档三项证据执行。

## 重叠能力路由

### PPT/PPTX

1. 教学目标、实验讲解、习题讲评、课堂总结：`custom-teacher-courseware-ppt` 作为 router/workflow。
2. 真实 `.pptx` 文件读写：managed `pptx` 或 plugin `Presentations` 作为 executor；plugin 可用且需要其 render/verify 工作流时优先 plugin。
3. 打开中的本机 PowerPoint、COM、模板和 overflow review：`powerpoint-automation`，仅交互桌面。
4. 图片化 deck：`baoyu-slide-deck`；不要把它误作可编辑 PPTX。
5. 禁止组合：无人值守 Office COM + 服务/计划任务；同一文件不得由多个 executor 并发写。

### Web/browser

1. 依赖当前 Chrome 登录态或扩展：plugin `control-chrome`。
2. Codex 内嵌浏览器、本地页面可见交互：plugin `control-in-app-browser`。
3. 编写/维护 Playwright 测试：`playwright-best-practices` + repo test runner。
4. 终端一次性无状态自动化：managed `playwright` 或 `agent-browser`，二选一；按现有项目脚本优先。
5. Playwright MCP：仅专项、isolated、最小 tool allowlist；默认 disabled。
6. 禁止组合：多个 operator 并发控制同一 profile；不可信网页与敏感登录态放在同一上下文。

### Windows desktop

1. 领域设计与实现：`custom-windows-wpf-teacher-app`。
2. E2E 设计与 UIA/pywinauto validator：`windows-desktop-e2e`。
3. 当前可见人工操作：plugin `computer-use`，必须保留用户可见性和误操作回滚。
4. WinAppDriver：不进入全局 skills/MCP；只有 repo-local 专项验证有硬需求时另行评审。

### 文档与资料检索

1. Microsoft 技术：enabled `microsoft-learn` MCP + `microsoft-docs`/`microsoft-code-reference`。
2. OpenAI 技术：enabled `openaiDeveloperDocs` + system `openai-docs`。
3. 其他公共库且版本特定：先官方网页/官方仓库；确有检索缺口再临时启用 Context7，query 必须去敏。
4. 本地 Office/PDF 转 Markdown：`markdown-converter` 或相应 plugin，不添加 MarkItDown MCP。

## `do_not_install`

| 候选 | 原因 | 重评条件 |
|---|---|---|
| Microsoft MarkItDown MCP | 已有同引擎 skill 与格式 plugins；MCP 只有单工具，却扩大 `file/http/data` URI 访问面；当前 wrapper 仍是 pre-release | 出现跨宿主结构化 tool-call 硬需求，现有 CLI skill 无法满足，并能用只读容器完成隔离 |
| Microsoft WinAppDriver | 不是 MCP；稳定版和维护状态过旧；需 Developer Mode/本机服务；已有 UIA/pywinauto 与 computer-use | 单仓 E2E contract 明确依赖 WebDriver 协议，Windows 11 支持和维护状态有新官方证据，并提供 repo-local 启停/回滚 |
| Remotion 子技能重复登记 | 根 skill 已含渐进披露路由；独立登记会增加 metadata 和触发竞争；live inventory 未把它们证明为独立对象 | schema/投影正式支持 nested skill 独立治理，并有兼容迁移、触发评测与回滚 |

## 风险小结

- 权限：filesystem root `D:\CODE` 过宽；Playwright/browser 能接触登录态与下载；WinAppDriver/desktop operator 能操作真实桌面；MarkItDown MCP 能按当前用户权限读取 `file:`/网络 URI。
- 隐私：Context7 会外发去敏后的 query 和 client metadata，并使用第三方 LLM reranking/匿名质量数据；不应发送私有项目名、代码、凭据或内部设计。
- 供应链：当前 disabled MCP 中存在 `npx -y`、`@latest` 未锁定形式。disabled 阶段不执行包，但任何启用前都应先锁版本、核验 hash/release 和 license。
- Windows：filesystem/Context7 官方排障建议 `cmd /c npx`；WinAppDriver 只明确 Windows 10；PowerPoint COM 必须交互桌面；MarkItDown MCP 没有专门 Windows 支持承诺。
- 账号/密钥/成本：Context7 有 API key、额度和付费层；MarkItDown 核心本地免费，但 Azure/LLM optional 路径会用 key/计费；Playwright/filesystem/WinAppDriver 本体不要求云账号，但访问的目标系统可能要求账号。
- 维护：Playwright、Context7、filesystem、Remotion 上游活跃；MarkItDown 主包活跃但 MCP wrapper 为 pre-release；WinAppDriver 维护证据不足。
