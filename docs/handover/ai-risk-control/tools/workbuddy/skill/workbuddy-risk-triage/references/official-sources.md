# 官方渠道、协议条款与外部证据

> 本文件是 `workbuddy-risk-triage` 的参考材料，按需读取。

## 官方反馈渠道

- 客户端：`帮助 -> helpFeedback` 或 `头像 -> 设置 -> 帮助与反馈 -> 意见反馈`（**勾选上传日志**）
- 邮箱：`workbuddy@tencent.com`（账号/积分）、`workbuddy_ai@tencent.com`（报错/Trace ID，**写进标题**）
- 内置诊断：`帮助 -> 诊断工具`，报告在 `logs/self-check/`
- 错误码页：`https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Error-Code`
- 服务协议：`https://www.workbuddy.ai/document/term`

**报错时第一件事是截图留证 + 停止重试。**
（「提交截图约 1 小时解封」这一说法流传较广，但**未找到可核实来源**，且另有一次检索得到「0 例成功」——两边都不足采信，不要当成承诺。）

### 国际版对应内容

| 条款 | 禁止内容 |
|---|---|
| **6.4(a)** | 反编译 / 反汇编 / 试图提取源码 |
| **6.4(d)** | 用 data mining / robots 等自动化或程序化方法提取数据 |
| **6.4(f)** | 抓取服务或系统信息，**或试图破译客户端与服务器之间的传输**（= 抓 Token） |
| **6.4(j)** | **绕过限制或保护措施** |
| **5.2(a)** | *will not seek to circumvent such technical precautions in any manner* |
| **3.5** | 服务**内置检测「规避手段 / 未授权及恶意程序」**，检测到会回传账号 + 用户 ID + 程序信息 |
| **6.3** | 禁止把服务转让给他人（含出租/出借/转卖） |
| **12.1** | 处置阶梯：警告 → 限制功能 → **封禁账号** → **禁止重新注册** → 终止协议 |
| **12.2** | 处罚时点与力度**由腾讯单方裁量**，参考违规严重程度**与违规次数** |
| **11.3** | 终止后果：必须停止使用并卸载；**不再有任何账号访问权**（协议**未**规定积分/余额如何清算） |

> ⚠️ **12.2 的「违规次数」是关键** —— 它意味着**反复触发会把可恢复的轻度限制升级为不可恢复的封禁**。
> 这也是「报错后反复重试」有害的协议依据（叠加 **5.3 合理使用**条款）。

## 官方对「低价积分 / 中转站」的公开定性（可直接引用）

中央广播电视总台中国之声 2026-09-11 报道
《250元的AI工具积分只卖8.8元？小心你的代码被截留倒卖》（科技日报等转载），
其中 **WorkBuddy 官方回应原文**：

> 通过终端脚本修改本地配置实现"积分到账"，实际属于接入外部模型，并不存在"WorkBuddy官方积分到账"的情况。
> 当前，已经升级产品策略，对违规行为坚决打击，**一经发现会做封号处理**。

同报道给出的风险链条：**一键安装脚本 → 篡改本地配置 → 接入第三方中转站 → 办公内容（文档/代码/会议纪要）被截留倒卖**；
并列举变体：卖「无限积分配置教程」、直接卖成品独立账号（3.88–7.88 元，来源不明）。

这条报道是**「反代 / 中转 / 低价积分 = 封号」的官方口径证据**，比任何社区帖都硬。

## 社区交叉验证（与本流程结论一致）

| 来源 | 结论 |
|---|---|
| 腾讯云开发者社区问答（2026-08，错误码 11140） | 「11140 的含义是**请求非法**，你的请求**还没发到模型**就被服务端拦截」；重装 / 清缓存 / 换自定义 API **都没用**；最可能原因：内容安全审核 / 多设备异地登录 / 高频调用；**有效动作**：提交 Trace ID 工单 → 停 2–4 小时 → 换手机热点测一次 → 退出重登确认没有多设备同挂 |
| Linux.do 帖（2026-09-19，403 request illegal） | 与本次事件同形态：单机、只装一个客户端，两天后被风控 |
| GitHub `workbuddy2api-hub` issue #25（2026-09-18） | 反代工具使用者「还能登录但什么对话都发不了」—— **反代 → 账号级封禁的实证** |

## 关键信息边界（防止过度推断）

- **官方对账号级风控不公开细则**：错误码页里没有 11140 / 403。任何声称「精确知道 11140 触发阈值」的说法都不可采信。
- **429 有明确 reset 时间**，403 没有 —— 两者处置路径不同，不要互相套用。
- 「静默降智」**没有官方承认也没有硬证据**；可确证的惩罚是显式的 11140 / 403 / 429。
