# 给另一台电脑上 AI 的提示词

把下面「提示词正文」整段复制给那台机器上的 AI 即可。
**先替换两处占位符**：`<交接包目录>`（本文件夹的绝对路径）、`<是否国际版>`（见下方第 0 步）。

---

## 提示词正文

你是运维/安全工程师。本机的 **WorkBuddy（腾讯 AI 客户端）** 出现过账号风控，我需要你在**这台机器**上复现同样的排查与加固。这是一个**诊断 + 加固**任务，不是聊天任务。

### 背景（已在前一台机器上确诊，不要重复推翻）

三类报错 `11140 内容未通过安全审核` / `403 request illegal (hex/UUID)` / `未知错误暂无响应`
**是同一个根因**：服务端**账号级风控拦截**，请求**在到达模型之前**就被丢弃。

已确诊的关键点（有证据，别重新怀疑）：

- 真实错误体在 `~/.workbuddy-ai/logs/<日期>/sdk/conversations/<会话UUID>.log`，形如
  `runtime.applyStopReason ... "event":"TURN_ERROR","stopReason":"refusal" ... {"code":-32603,...,"statusCode":403,...,"code":11140,"category":"internal"}`
- **`category` 是 `internal`，不是内容审核类目** —— 显示的「内容未通过安全审核」是通用包装文案，**不要照字面理解成内容违规**
- `details` 里的 UUID **等于该会话自己的 UUID**，不是用户级令牌；「同一 UUID 跨多日出现」通常只是用户把报错原文粘贴进了新会话标题（**这是最大的推理陷阱**）
- 连只发「你好」的会话也是同一条 11140/403 → 内容变量排除 → **只能是账号级**
- 因此这些操作**全部无效**：重装客户端、清缓存、退登重登、换自定义模型/第三方 API
- **唯一有害的动作是反复重试/重启**，会被计入异常行为特征

### 先分清：429 与 403 是两件事（**不要混判**）

| | 403 / 11140 | 429 |
|---|---|---|
| 性质 | 未公开细则的**账号级风控** | 官方承认的**频率/额度限流** |
| 是否给恢复时间 | 否 | **是**，形如 `reset at 2026-09-30 21:49:20 UTC+8` |
| 官方清单 | **不在**（错误码页查不到） | 同族见 6003 / 6004（「专业版也会出现」） |
| 处置 | 换号 / 申诉工单 / 停 2–4 小时 | **等 reset + 切模型 + 把长任务切段** |

429 的错误体格式与 403 相同（`(32位hex/会话UUID)`，UUID 仍是**会话 ID**）。
实测同一天出现过 `05:56` 与 `21:49` 两个 reset 点 → 限流窗口有**长周期额度**与**短周期频率**两种尺度。

### 换号只能止血，不能根治（**最容易漏判**）

**换账号解决的是「这个账号被标记了」，解决不了「这套用法会被标记」。**

实测对照：旧账号被风控后换新号，新号 403/11140 **归零**（证明是账号级），
但新号的会话主题分布与旧号**同源**（旧号「fq 网关 key / CLIProxyAPI / CPA 网关 / OAuth」，
新号仍是「审查 CPA 网关 / 升级 CLIProxyAPI / 修改 CPA 路由」）。**行为画像原样搬了过去。**

所以判「是否已彻底修复」必须分两层：**止血**（403 归零、环境项全绿）与
**根治**（新增会话是否已脱离触发画像那一簇）。配套动作：**把反代 / 网关 / 密钥 / 绕过类工作
彻底移出 WorkBuddy 会话。**

### 第 0 步：先确认版本（决定域名后缀）

```bash
grep -o -h -E 'https?://[a-zA-Z0-9._-]+' ~/.workbuddy/logs/*/[a-z]*.log \
  | sed 's#https\?://##' | sort | uniq -c | sort -rn | head
```

`www.workbuddy.ai` = 国际版；`www.workbuddy.cn` = 国内版。**必须先确认再判断代理规则对不对。**

### 第 1 步：跑自检，拿到基线（只读，不改任何文件）

```bash
bash "<交接包目录>/tools/workbuddy-risk-selfcheck.sh"
```

退出码 `0` = 无高危，`1` = 有高危。脚本覆盖 9 项：hosts 劫持、自定义模型/反代进程、第三方指向、
多账号共用设备指纹、代理例外、**代理例外覆盖缺口**、重启频率、**真实 403/11140/429**、自动化与 MCP 认证重试。

若代理客户端不是 v2rayN，用 `V2RAY_CONFIG=<配置文件路径>` 指定，或忽略该项。
**不要一上来就改任何东西**，先出基线报告。

### 第 2 步：按结果处理（只处理标 `[高危]`/`[注意]` 的项）

| 自检结果 | 处置 |
|---|---|
| hosts 含 workbuddy/codebuddy/tencent 条目 | 高危，灰产「积分充值」劫持，清除并排查来源 |
| `models.json` 非空 | 高危，接了反代/中转，官方明确封号 |
| 反代类进程（workbuddy2api / proxy 等） | 高危，立即停用并轮换凭据 |
| `settings.json` 含 baseUrl/apiKey/endpoint | 核对是否指向非官方服务 |
| 账号数 > 1 | 同设备多账号是「账号关联」特征，**不要再切号、不要新注册** |
| 代理例外缺域名 | 见第 3 步 |
| 今日启动 > 8 次 | 停手，不要靠重启来试 |
| 真实日志命中 403/11140 | 见第 4 步 |

### 第 3 步：代理例外必须**两层都覆盖**（最容易漏）

这套客户端里 **Chromium 侧读系统代理（WinINET `ProxyOverride`）**、**Node 侧读环境变量
（`HTTP_PROXY`/`NO_PROXY`）**。两层是**两套独立机制**，任一层漏域名，该层流量就走代理。
必需覆盖的域名（按第 0 步结果取后缀）：

- `workbuddy.<ai|cn>`、`codebuddy.<ai|cn>`
- `lkeap.cloud.tencent.com`（模型 API 端点，实测确凿，两层都要有）

**修法（必须双写，否则代理客户端重启会把注册表改回去）：**

1. WinINET：给 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings\ProxyOverride`
   追加 `*.lkeap.cloud.tencent.com`（立即生效）
2. 代理客户端：同步追加到它的「系统代理例外」配置里（v2rayN 是
   `guiConfigs/guiNConfig.json` 的 `SystemProxyItem.SystemProxyExceptions`）

**改前先备份。** 本机 `reg.exe` 若被安全策略拦截，用 Python `winreg` 读写：
```python
import winreg
k = winreg.OpenKey(winreg.HKEY_CURRENT_USER,
    r"Software\Microsoft\Windows\CurrentVersion\Internet Settings", 0, winreg.KEY_READ|winreg.KEY_WRITE)
```

验证两条：
```bash
curl -s --noproxy '*' https://myip.ipip.net          # 直连出口
curl -s -x http://127.0.0.1:<代理端口> https://ipinfo.io/json   # 代理出口
```
两个 IP 若分别属于国内外不同地域，说明「混合出口」风险仍在。

### 第 4 步：判定是不是账号级（不要靠猜）

```bash
grep -riE 'bizCode=11140|statusCode.?":?403|refusal classified' \
  ~/.workbuddy-ai/logs/*/sdk/conversations/*.log
```

- 看 `category`：`internal` = 风控，不是内容审核
- **新开一个会话只发「你好」**也报同样的错 → 账号级（内容变量排除）
- **同机换一个账号**能用 → 账号级；仍不能用 → 设备或网络级（先查第 3 步的例外是否被重写）

⚠️ **不要在 `~/.workbuddy-ai/logs/` 全目录搜**：会话日志会记录你自己执行过的命令，
你 grep 过这些字符串就会被自己命中（实测假阳性 112 条 → 真实仅 14 条）。

### 第 5 步：验收

```bash
bash "<交接包目录>/tools/workbuddy-risk-selfcheck.test.sh"    # 受控验收（35 用例），应 PASS 全绿
bash "<交接包目录>/tools/workbuddy-risk-selfcheck.sh"          # 复跑，确认高危归零
```

判据：连续 3–7 天无 11140/403/429、长会话不断流、每日自检高危 0。

> 受控验收在沙箱环境约需 15 分钟（每外部命令约 100ms 开销，非脚本缺陷）。

### 红线：以下绝对不要做（碰了会把「临时限制」升级为「永久封禁」）

**先确认是哪一份协议，再引编号** —— 两份并行协议编号不同：

- **WorkBuddy 国际版**（`www.workbuddy.ai/document/term`）：**6.4(a)(d)(f)(j) / 5.2(a) / 3.5 / 6.3 / 12.1 / 12.2**
  （`.cn` 站同页也是英文版，且 16.6 条明确英文版优先效力）
  - 6.4(f) 抓取客户端与服务器之间的传输（= 抓 Token）；6.4(j) 绕过限制或保护措施
  - **3.5**：服务内置检测「规避手段 / 未授权及恶意程序」，检测到会回传账号 + 用户 ID + 程序信息
  - **12.2**：处罚参考违规严重程度**与违规次数** → **反复触发会把可恢复的轻度限制升级为不可恢复的封禁**
- **CodeBuddy / 腾讯云代码助手系**（中文协议，`https://rule.tencent.com/rule/202603180001`）：
  **9.2(2)** 程序化提取数据 / **9.2(6)** 绕开技术保护措施 / **9.2(8)** 修改伪造客户端指令或数据；
  **8.1.2** 账号仅限本人使用、不得超量注册、不得出租转卖；处置梯度见 **9.4.1**
  （与 WorkBuddy 账号体系互通，一侧违规影响另一侧）

所以**不要**：改 hosts 接灰产「低价积分/源头充值」、装反代/中转/Token 提取工具、
**伪造 `device-id` 摆脱账号关联**、篡改客户端状态、批量注册、账号共享、**报错后反复重试/重启**。
这些不但没用（服务端已有账号↔设备↔网络多维映射），还会把可恢复的风控变成不可恢复的封禁。

> ⚠️ **官方对「低价积分 / 中转站」的公开定性**（中央广播电视总台 2026-09-11 报道中 WorkBuddy 官方回应原文）：
> 「通过终端脚本修改本地配置实现"积分到账"，实际属于接入外部模型……已经升级产品策略，
> 对违规行为坚决打击，**一经发现会做封号处理**。」
> 风险链条：一键安装脚本 → 篡改本地配置 → 接入第三方中转站 → **办公内容（文档/代码/会议纪要）被截留倒卖**。

### 三条已踩过的坑，别再踩

1. **不要把 `NO_PROXY` 改成 `*.` 通配符形式。** Python `urllib`、Node `proxy-from-env`、
   Go `httpproxy` 走的是「主机名以 `.域名` 结尾」的后缀匹配，裸域名 **本来就能覆盖子域**；
   写成 `*.workbuddy.ai` 后它们去找字面量 `.*.workbuddy.ai`，**永远匹配不上，等于取消例外**。
2. **不要擅自删全局 `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`。** git / npm / pip 依赖它们访问境外源，
   删了会立刻打断这些工具。改为：保留它们 + 保证 `NO_PROXY` 覆盖完整 + 让脚本持续告警。
3. **不要装网上那些「429 限流稳流器」**（如 **FlowRebound**，掘金/知乎/CSDN 上有大量雷同软文推销）。
   它们的核心步骤是「把 WorkBuddy 的**自定义模型地址换成工具的本地地址**」——
   这是把请求改道经第三方本地代理，属「绕过限制措施」，与「低价积分」灰产同一套手法。
   **它是封号加速器，不是限流解决方案。** 自检脚本已把 `flowrebound` 列入反代类进程检测项。
