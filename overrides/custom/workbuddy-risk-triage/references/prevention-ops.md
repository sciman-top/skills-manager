# 主动防范操作手册（WorkBuddy / CodeBuddy）

> 本文件是 `workbuddy-risk-triage` 的参考材料，按需读取。
> 定位：**出事之前**的日常守则与环境配置核查单；出事之后的分诊见 SKILL.md 主体。

## 一、账号与环境初始配置核查单（Pre-flight checklist）

首次使用或换机器时，按下表逐项确认。全绿才算"干净起点"。

| 项 | 检查内容 | 标准 |
|---|---|---|
| **客户端版本** | 国际版（`.workbuddy.ai`）还是国内版（`.workbuddy.cn`）| 先确认版本，代理规则、条款条款号因版本而异 |
| **单账号原则** | 本机是否只有一个账号在用 | **不多账号共用设备**；有多账号就不要再切换/新注册 |
| **反代进程清零** | `workbuddy2api` / `workbuddy-proxy` / `flowrebound` 进程 | 全部停止并卸载 |
| **自定义模型清零** | `~/.workbuddy/settings.json` 里的 `baseUrl`/`apiKey`/`endpoint` | 确认指向官方地址，不含第三方接口 |
| **models.json** | `models.json` 是否非空 | 空 = 没有接反代，否则高危 |
| **hosts 文件** | `/etc/hosts` 或 `C:\Windows\System32\drivers\etc\hosts` | 不含 workbuddy/codebuddy 相关条目（灰产劫持特征）|
| **代理例外双层** | WinINET `ProxyOverride` + 环境变量 `NO_PROXY` | 两层都覆盖目标域名（见下方清单）|
| **账号来源** | 账号是否自己注册 | 不用购买/租借/共享账号 |

### 代理例外域名参考清单

按客户端版本填入两层代理例外（WinINET 注配符 `*.domain`，NO_PROXY 裸域名）：

| 版本 | 必须直连的域名 |
|---|---|
| 国际版 | `workbuddy.ai`、`codebuddy.ai`、`lkeap.cloud.tencent.com` |
| 国内版 | `workbuddy.cn`、`codebuddy.cn` |

> 双层例外设置方法见 `network-and-proxy.md`。两层缺一会导致部分流量走代理出口，影响账号画像。

## 二、日常使用守则

### 2.1 遇到限流/报错的第一反应

```
第 0 步：截图留证 + 立即停止重试
```

**反复重试是唯一会让情况变坏的本地动作**（协议 12.2：反复触发把可恢复限制升级为不可恢复封禁）。

拿到截图后，先判断是 403/11140（账号级）还是 429（限流），两者处置路径相反：

- **429**：看 reset 时间，等到那个时间点；期间按官方建议切模型；**不要重试**。
- **403/11140**：换手机热点测一次（IP 级？）→ 换账号测一次（账号级？）→ 停 2-4 小时再试。

### 2.2 会话行为守则

| 行为 | 守则 |
|---|---|
| 遇到报错 | 截图 → 停止重试 → 等待或按 SOP 分诊，**不反复重启客户端** |
| 长任务 | 切段完成；每段结束确认没有 429/403 再继续 |
| 重任务 | 避开高峰时段（早 9-10 点、午 12-14 点、晚 20-23 点）|
| 模型选择 | 固定版本，不来回横跳；6003/6004 报错时官方建议切模型是合规手段 |
| 多账号 | **不要在同一台设备上切换多个账号**；已有多账号不要新注册 |

### 2.3 反代类工具的处置原则

如果过去用过任何反代/中转工具（`workbuddy2api` / `flowrebound` / 第三方「低价充值」等）：

1. **立即停用**，不只是关闭——要卸载，防止开机自启。
2. **轮换凭据**：假设 token 已被提取，去客户端重新授权。
3. **不要继续用同一个账号**：工具留下的画像已存在，换账号只是止血（见 SKILL.md "换号只能止血"章节）。

## 三、行为画像自查（防范复发的核心维度）

**封号/风控判的是「画像」，不是单次行为。** 换号止血之后，新号的画像要主动脱离触发那一簇：

| 检查项 | 问题 |
|---|---|
| 最近 30 个会话主题 | 是否集中在"反代/网关/CLIProxyAPI/CPA/OAuth/密钥提取"类？ |
| MCP 连接器列表 | 是否有非官方的外部连接器启用？（官方内置插件 `ardot`/`miora` 未配令牌属正常）|
| 今日客户端启动次数 | 是否 > 8 次（反复重启是高危信号）|
| 当前进程列表 | `workbuddy2api` / `workbuddy-proxy` / `flowrebound` 是否仍在运行 |
| hosts 文件 | 是否含 workbuddy/codebuddy 相关条目 |

**配套动作**：把反代/网关/密钥/绕过类工作**彻底移出 WorkBuddy 会话**，放到本地终端或独立工具里做。

## 四、自检脚本的正确用法

自检脚本随交接包分发：仓库检出内为 `docs/handover/ai-risk-control/tools/workbuddy/workbuddy-risk-selfcheck.sh`；已部署机器上通常为 `D:\TOOL\workbuddy-risk\workbuddy-risk-selfcheck.sh`。

```bash
bash "<风控工具目录>/workbuddy-risk-selfcheck.sh"
```

**建议使用频率**：
- 首次配置后跑一次，建立基线（全项绿才算干净起点）
- 遇到任何异常报错之前先跑一次
- 换号/换机后跑一次

**正确解读结果**（常见误判）：

| 误判场景 | 正确判读 |
|---|---|
| 429 计数写完文档/跑命令后突然上涨 | **先怀疑自污染**（会话日志记录了你写的文本）；看命中行首是否是 ISO 时间戳 |
| `ardot` / `miora` MCP 认证失败报高危 | 这是内置插件未配令牌的**预期行为**，不是风控信号 |
| `netdrive` / `genie-baas` MCP 认证失败报高危 | 这是官方网关连接器的**预期行为**，不是风控信号 |
| 启动次数异常高 | 确认是否沙箱/CI 环境造成的计数虚高 |

详细拆解见 `references/selfcheck-internals.md`。

## 五、直连守护与整机代理维护

WorkBuddy 五域的目标状态是**直连**，不是挑一个代理出口：官方错误码页对 3002/3003/3007 的建议就是「关闭网络代理」，本机直连部署后真实 API 错误归零（已验证例外表见 `network-and-proxy.md`）。对 WorkBuddy 而言代理是**风险来源**——例外表被冲掉，流量就会落到代理出口 IP，形成画像异常信号。

**日常维护要点**：

1. **开工前确认五域仍在双层例外表内**（WinINET `ProxyOverride` + `NO_PROXY`；自检脚本已含该检查）
2. **v2rayN 双写**：改例外表必须同步 `guiConfigs/guiNConfig.json` 的 `SystemProxyExceptions`，否则 v2rayN 重启会把注册表改回去
3. **整机代理健康影响的是其他流量**（如 Antigravity）：代理死时系统代理必须立即回退到常驻前端（自愈双向），否则整机断网
4. **不频繁切换出口区域节点**：短时间横跳多国节点对走代理的流量是画像异常信号

验证直连生效（WorkBuddy 流量应命中直连出口，而非代理出口）：

```bash
# 直连出口 IP（应为本地宽带 IP）
curl -s --noproxy '*' https://myip.ipip.net
# 代理出口 IP（WorkBuddy 域名不应从这个出口出去）
curl -s -x http://127.0.0.1:<端口> https://ipinfo.io/json
```

进程级归因（确认 WorkBuddy 客户端进程没有连代理端口）见 `references/network-and-proxy.md`。

## 六、信息污染识别速查

遇到声称能"防风控/防封号/防限流/解除限制"的工具或文章，用三个问题快速判断：

| 问题 | 如果是 | 结论 |
|---|---|---|
| 核心步骤是不是「把接口地址换成本地/第三方地址」？ | 是 | **封号加速器，划走**（协议 6.4 明文禁止）|
| 卖点是不是「多账号/稳流/无限使用/绕过限制」？ | 是 | **划走** |
| 教你改 hosts 或使用「低价积分/源头充值」？ | 是 | **红线，灰产，立即停止** |

黑名单关键词（见到就停）：`workbuddy2api`、`workbuddy-proxy`、`flowrebound`、`FlowRebound`、「稳流器」、「低价积分/源头充值」、「自定义模型换本地地址」。
