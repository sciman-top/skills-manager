# 验收与投影：把「改完了」证成「可靠」

适用场景：任何**网络出口加固 / 自愈脚本 / 计划任务**类改动。核心问题是——
**「脚本跑通了」和「没人看着时它也会自己修好」是两件完全不同的事。**

## 一、真值层级（先对齐用词）

```
repo_verified  ->  filesystem_projected  ->  host_loaded  ->  live_accepted
  代码/配置对        文件已落盘              宿主真的加载了     长期无事故
```

- **`host_loaded` 是「机制正确」**，可以一次跑完拿到。
- **`live_accepted` 是「时间正确」**，只能等（跨过限流窗口、调度波动、真实使用强度）。
- **把两者混为一谈就是自欺。** 报告里必须分开写。

## 二、三层验收 + 一次投影

| 层 | 证明什么 | 是否碰真实系统 | 时长 |
|---|---|---|---|
| ① 受控验收（离线夹具） | **脚本的判定逻辑**正确 | 否 | 秒级 |
| ② 受控实战验收（真故障注入） | **整套自动化**真能自愈 | 是（自动收尾） | 分钟级 |
| ③ 全量自检 | 当前状态无 FAIL | 只读 | 秒级 |
| ④ 投影校验 | 交付物与源机**无漂移** | 只读 | 秒级 |

**为什么 ① 和 ② 都要**：① 证「**脚本能修**」，② 证「**没人看着时也会被修**」。
自动化真正的价值在后半句 —— 只做 ① 等于没验自动化。

## 三、受控验收（离线夹具）怎么做

### 前置：把被测脚本改成「可注入」

这是**必做的前置改造**，否则测试会污染真实系统。要参数化的东西：

- **端口**（`-Port`）
- **路径**（内核、配置、日志、备份）
- **注册表键**（`-ProxyRegPath` —— 测试时指向临时键）
- **环境变量作用域**（`-EnvScope`，测试用 `Process`：进程结束即消失）
- **副作用开关**（`-NoStart` / `-NoEnvWrite` / `-NoStartupLnk` / `-NoEgressProbe`）

不传参数时用默认值，**行为必须与改造前完全一致** —— 改完要跑一次真实环境回归确认。

> ⚠️ **改造被测脚本时不要删掉这些参数**，否则验收立刻失效。

### 夹具构造

| 需要的状态 | 怎么造 |
|---|---|
| 「服务在跑」 | 在本进程起一个 `TcpListener` 绑 127.0.0.1:0，**保持监听** |
| 「服务不在跑」 | 绑 0 端口取到端口号后 **立即 `Stop()`**（端口空着） |
| 注册表初始状态 | 临时键 `HKCU:\Software\_xxx_test_<用例名>`，用完删 |
| 文件存在/缺失 | 临时目录里建/不建 |

### 断言要断三层

1. **输出子串**（日志/控制台里出现预期结论）
2. **退出码契约**（就绪 = 0，有未完成 = 1）
3. **副作用实际值**（读回注册表/文件，确认真的改了，而不是只打印了一行）

### 用例设计要点

- **每个判定分支至少一个用例**，包括「什么都不该做」的分支。
- **反向用例必做**：安全阀、回退、降级路径 —— 这些平时不触发，最容易被写错。
- 覆盖「缺文件 / 参数非法」的**前置校验**分支。

### 坑

- **用例本身可能写错。** 实测踩过：`-EnvScope Process` 时子进程继承的是**父进程真实环境变量**，
  所以「env 已正确」这个用例永远不可能命中 —— 需要在调用前先在测试进程里把变量设成目标值。
  **首轮 FAIL 先怀疑用例，再怀疑被测代码。**
- 临时注册表键必须**在 finally/末尾清理**，否则污染后续。

## 四、受控实战验收（真故障注入）怎么做

### 关键：测「自动化」而不是「脚本」

| 项 | 注入 | 断言 |
|---|---|---|
| 手动自愈 | 杀掉服务进程 | 跑一次自愈脚本 → 恢复 |
| **自动化自愈** | 杀掉服务进程，**然后什么都不做** | **等真实看门狗（≤周期）自动恢复** |
| **安全阀** | 把系统代理临时指向死端口 | 自愈脚本必须**回退到常驻前端** |
| 正确性 | — | 关键业务指标仍正确（如出口分流不同网段） |

### 安全设计（**必须**）

- 全程 `try { ... } finally { 恢复 }`。
- `finally` 里**无条件**把系统恢复到已知良好状态；恢复不了就走降级路径（回退代理），
  **绝不把机器留在断网状态**。
- 报告里要写清「本次注入过什么、怎么恢复的」。

## 五、投影（交接包）

1. 把新增/变更的脚本与文档同步进交接包目录。
2. 生成 `MANIFEST.sha256`（`<相对路径>  <sha256>`，含 tools 与文档）。
3. **逐项与源机比对**，确认 `DRIFT = 0`。

校验片段（可直接放进 PROMPT）：

```powershell
cd <包目录>
Get-Content MANIFEST.sha256 | ForEach-Object {
  $p,$h = $_ -split '\s+',2
  $a = (Get-FileHash $p -Algorithm SHA256).Hash.ToLower()
  if ($a -eq $h.ToLower()) { "OK   $p" } else { "DRIFT $p" }
}
```

**注意**：`MANIFEST.sha256` 不能包含自己。

## 六、一条通用的自检反模式

**「文件在不在」类判据会给假保证。**

实测踩过：自检脚本检查「Startup 里的快捷方式存在」就报 PASS ——
但在**快速启动**（`HiberbootEnabled=1`）下 Startup 项根本不会被执行，分流器从来没起来过。

→ **判据必须是「实际有没有跑起来」（进程/端口/任务状态），不是「配置有没有写」。**
