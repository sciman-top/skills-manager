# 日常使用与风险控制

## 先确认正确的产品路径

1. **核对服务资格。** 对照 [Antigravity FAQ](https://antigravity.google/docs/faq/) 的当前支持地区、年龄和账号要求。FAQ 目前面向个人 Google Accounts；Workspace 登录遇到问题时按 FAQ 指引处理。不要把代理切换、虚构地区或更改设备标识当成资格修复。
2. **使用官方支持的访问方式。** 使用 Antigravity 官方客户端和认证；官方 FAQ 允许 agy -p 直接用于脚本/CI，但消费计划不支持将它包装进第三方 agent/应用或自动轮换账号。
3. **第三方 coding agent 走独立的官方产品入口。** 使用该 agent 支持的 Google AI Studio Gemini API key 或 Gemini Enterprise，并遵守该产品的条款、配额与计费规则。不要把 Antigravity 订阅 OAuth/token 暴露给网关或其他客户端。
4. **核对实际额度面。** Antigravity 看产品内 Settings/Usage 和当前 plan；Gemini API 看 AI Studio 对应 project/model；Gemini CLI 看其当前官方额度说明。不同入口的额度不可互相代替。
5. **控制任务成本。** Antigravity 官方说明额度与 agent 完成工作量相关，复杂任务会消耗更多额度，限制也可能随容量调整。把大目标拆成明确小步，压缩无关上下文，减少不必要并发；这有助于计划用量，不构成账号安全保证。
6. **设置 credits 消费偏好。** Antigravity Pro/Ultra 计划可在 AI Credit Overages 设置 Never 或 Always。若不希望基线用量耗尽后自动产生额外消费，确认设置为 Never；先查看当前值，再决定是否需要更改。
7. **把网络与账号资格分开。** 仅在服务支持且当地规则允许时，按正常系统/组织网络配置解决连通性问题。稳定网络可减少连接错误，但没有官方证据表明固定出口或第三方 IP 标签能降低账号处罚概率。不要为账号风险而注入 DLL、改客户端文件、使用 OAuth 网关或测试伪装指纹。
8. **保护凭据与证据。** API key 使用密钥管理工具，不提交仓库、不贴到日志或求助帖；分享错误时隐藏邮箱、token、project ID 和本地路径，只保留诊断所需时间、产品面、状态码与请求 ID。

## 遇到“封号 / 限流 / 降智”时

- **明确 ToS/service disabled**：停止被拒服务请求，记录原始但脱敏的错误和时间，使用当前官方支持入口；不重复登录尝试、不通过另一账号继续同一自动化任务。
- **普通 403**：检查认证、权限、账号/计划资格、地区、API key/project、计费和端点；不能仅凭状态码判定封号。
- **429**：确认产品及模型，查看官方用量/重置提示，停止重复提交直到窗口恢复。API 程序按官方提示做有上限的退避；UI 任务不要用脚本反复点击或自动切号。
- **连接失败**：验证系统代理/组织网络和官方服务状态。对单个网络端点的探测不能证明实际客户端已登录或模型请求成功。
- **输出变差**：记录模型选择、计划/额度、时间、任务、材料和上下文长度；开启短的新对话做一次低成本、同条件对照。不要用压测、反复重启或长串 benchmark 消耗额度。

## 不作为风控依据

- 单机登录账号数、同一 GCP project 的成员数、会话标题/话题、重启次数。
- IP 数据库的 hosting/proxy 标签、DNS ECS、HTTP 404 或单一端点连通性。
- 社区推测的 TLS/HTTP 指纹、账号关联模型、检测阈值、固定出口、“住宅 IP”或自动恢复时限。

这些信号可以有各自的网络或产品管理用途，但官方没有说明它们能预测个人账号是否会被暂停。
