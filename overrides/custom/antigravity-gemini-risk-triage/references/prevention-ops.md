# 主动防范操作手册（Antigravity / Gemini）

> 本文件是 `antigravity-gemini-risk-triage` 的参考材料，按需读取。
> 定位：**出事之前**的日常守则与环境配置核查单；出事之后的分诊见 SKILL.md 主体。

## 一、账号与环境初始配置核查单（Pre-flight checklist）

首次使用或换机器时，按下表逐项确认。全绿才算"干净起点"。

| 项 | 检查内容 | 标准 |
|---|---|---|
| **账号类型** | 用 `@gmail.com` 还是 Google Workspace | 优先 `@gmail.com`；Workspace 账号可能年龄验证失败 |
| **年龄验证** | `myaccount.google.com/age-verification` | 完成验证，≥18 岁 |
| **地区关联** | Google 服务条款页显示的国家 | 确认与实际使用地区可对应；中国大陆需代理 |
| **单账号原则** | 本机/本会话只挂一个 Antigravity 账号 | **不开 account switcher，不多账号并行** |
| **GCP project 隔离** | 账号对应的 GCP project | **每个账号对应独立 project**，不共享 |
| **第三方工具清零** | OpenClaw / CLIProxyAPI / Zerogravity / OpenCode / gcl2api-plus | 全部移除或彻底断开 Antigravity OAuth |
| **出口代理质量** | 出口 IP 的 `hosting`/`proxy` 字段 | 两项均 `false`（非机房/代理特征）才适合给 Google 走 |
| **出口固定性** | 是否频繁横跳不同国家节点 | 同一账号固定一个出口区域，不来回切换 |
| **Antigravity 版本** | 当前安装版本 | 保持最新；旧版有限速后循环卡死 bug |

验证出口 IP 质量的命令（见 `ban-mechanics.md` 第六节）：

```powershell
# 查出口 IP 质量（两项都 false 才干净）
curl "http://ip-api.com/json/<出口IP>?fields=status,isp,org,as,hosting,proxy"
# 查 Google 侧实际看到的网段
curl -x http://127.0.0.1:<代理端口> "https://dns.google/resolve?name=o-o.myaddr.l.google.com&type=TXT"
```

## 二、日常使用守则（每次开工前过一遍）

### 2.1 配额意识

- **先看额度状态再开工**：`设置 → 模型 → 模型额度`，看"每周限额剩余/5小时限额剩余"百分比与刷新倒计时。
- **复杂任务 = 高消耗**：官方明确"额度与 agent 实际工作量相关，不是次数"。一句"帮我修好这个仓库"可能触发数十次请求。
- **主动降级节省 Pro 额度**：调研/汇总/格式化等轻任务主动选 Flash；把 Pro 留给真正需要多步推理的编码/分析任务。
- **超额路径只有两条（合规）**：等刷新（5小时/周）或购买 AI credits（`设置 → 模型 → 允许 AI 额度超限使用`）。

### 2.2 出口稳定性

- **代理进程在不在**决定整机网络是否正常 → 每天开工时确认代理进程存活（任务栏图标/端口在听）。
- **自愈脚本必须双向**：代理活着时设系统代理指向它；代理死了时立即回退到常驻前端——**不能让系统代理指向死端口**（等于断网）。
- 细节见 `ban-mechanics.md` 第六节（出口 IP 加固 10 条）。

### 2.3 会话行为

- **长任务切段**：估计一个任务会触发大量工具调用时，切成多个小目标分批完成，每段结束确认额度还够再继续。
- **避高峰**：高峰时段 Pro 配额紧张时系统会引导用 Flash/Flash Extended——重任务排到低峰期。
- **不要来回切模型**：固定一个模型版本跑一段时间，方便发现真正的变化；频繁横跳让"降智"无法归因。

## 三、行为画像自查（最容易被忽视的防范维度）

**封号判的是「画像」，不是单次行为。** 以下任意一项在会话记录里高频出现，就是在积累触发概率：

| 高危画像特征 | 自查方法 |
|---|---|
| 会话主题集中在"绕过限制/反代/OAuth/网关"类 | 看最近 30 个会话的标题/首句 |
| 频繁重试/重启（今日重启 >8 次） | 任务管理器看启动时间；日志看启动记录 |
| 同一 GCP project 下挂了多个账号 | Google Cloud Console → IAM → 成员列表 |
| 第三方工具的配置文件里仍有 Antigravity 槽位 | 找 `*_accounts/` 或 `*_accounts.json` 是否非空 |
| 本地端口有网关在监听并对外暴露 Antigravity 额度 | `netstat -ano | findstr LISTENING` + 排查暴露端口 |

**配套动作**：把反代/网关/密钥/绕过类工作**彻底移出 Antigravity 会话**，放到本地终端里独立完成。

## 四、Gemini API（AI Studio）日常用量管理

适用于用 API Key 访问的场景（官方推荐的第三方 agent 合规通道）：

- **RPD 重置时间**：太平洋时间午夜 = **北京时间下午约 16:00**。"今天额度用完了"要等到这个时间点，不是明天早上。
- **多建 API Key 无效**：限速按 project 计，不是按 Key 计。
- **排错权威入口**：`https://aistudio.google.com/rate-limit`（可查最近 28 天）。不要用第三方仪表盘。
- **升层级**：绑定计费账号 → Tier 1；累计付费 $100 且满 3 天 → Tier 2（10 分钟内生效）。满足条件通常自动升，极少数情况因审核中其他因素被拒。
- **环境变量冲突**：同时设了 `GOOGLE_CLOUD_PROJECT`/gcloud 配置 与 AI Studio API Key → CLI 走错路径，回落到受限免费层报 429。修法：清掉冲突变量，重新生成 Key（升层后在升层前生成的 Key 可能仍受限）。

## 五、当"感觉变笨"时的快速自查顺序

> 目标：10 分钟内排除最常见归因，避免把"配额耗尽/上下文长"误判成"风控降智"。

1. **看界面模型名**——确认现在跑的是 Pro 还是 Flash（不要靠回复速度猜）。
2. **看额度倒计时**——是否已触达 5 小时/周上限，系统引导了降级链。
3. **新建对话对照**——把背景压成一段摘要，用同一问题测试。若新对话正常 → 是上下文型。
4. **固定测试题**——同一问题、同一材料、同一格式，每轮只改一个因素再比较。
5. 仍然异常 → 看 `references/degradation.md` 完整归因流程。

**判据**：只有「新对话 + 同一模型 + 同一材料 + 同一提示词」仍连续出现相同错误，才值得怀疑产品侧。

## 六、信息污染识别速查

遇到声称能"防封号/防限流/恢复满血"的工具或文章，用三个问题快速判断：

| 问题 | 如果是 | 结论 |
|---|---|---|
| 它改的是「我怎么连上」还是「我以谁的身份、用多少额度」？ | 改身份/额度 | **红线，立即放弃** |
| 它的核心步骤是不是「把接口地址换成本地地址/中转地址」？ | 是 | **封号加速器，划走** |
| 它卖的点是不是「多账号池/自动轮换/无限使用/绕过限制」？ | 是 | **划走** |

黑名单关键词（见到就停）：`CLIProxyAPI`、`Zerogravity`、`OpenClaw`、`OpenCode`、`Antigravity Tools`、`Antigravity Rotator`、`Antigravity-Manager`、`gcl2api-plus`、`ANTIGRAVITY_MODEL_FALLBACK_CHAIN`（作为第三方工具卖点时）。
