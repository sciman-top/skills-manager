# 防范与日常操作

## 开工前

- 确认实际产品、官方客户端版本、认证路径和使用资格，分别核验 Antigravity、Gemini CLI、Gemini API/企业服务。
- 核对调用方是否复用 Antigravity OAuth；第三方工具使用正式 Gemini API 与复用订阅身份分别判定，不按工具名称拉黑。
- 读取对应产品额度和 AI credits 设置，明确费用意图；不把付费当作无限额度。
- 保持网络稳定，核对实际监听进程及路由。IP 分类、代理可达和全绿自检均不能证明账号安全；网络可达不代表地区资格。
- 不要求每个账号独立 project 作为防封措施，也不读取个人历史会话推测账号画像。共享 project 的配额需要统一计量，账号处罚因果关系未知。

## 执行中

先用一条任务主链，避免多个会话重复请求同一任务。长任务按可验收目标切段，减少无关日志、重复审查和工具失败循环。模型选择以当前任务、用户要求和官方可用性为准，不自动降级或切号重放。

遇到 429、auth、risk 或 billing 错误停止当前任务；保存脱敏错误、时间、版本和服务端等待提示。只在恢复条件满足并有当前授权时继续。503/网络故障按调用方合同处理，避免 SDK 与外层重试叠加。

## API 调用方控制

真正掌握请求链路的组件才能限制并发、队列、token 和费用。skills-manager 的 ai-risk-control 是只读建议，不拦截宿主请求；规则文本也不能证明实际限流。没有真实调用方与故障依据时不新建网关、调度器或常驻探针。

同项目多 Key 共享限额；RPD 重置按太平洋午夜，注意夏令时。配额管理依据官方面板，不为提额轮换密钥。认证疑点先核验实际路径，不批量删变量或凭据。

## 网络整改

官方支持的网络配置优先。客户端注入的合规性与维护风险需要单独说明，不当作防封工具。代理故障处置需保留既有网络连续性：先确认监听者与已知回退路径，再在明确授权下做备份、最小修改、读回和受控验证；不得为诊断主动杀生产进程。

DNS 查询或通用 IP 查询不能独立证明 Antigravity 模型连接实际使用的出口。检查范围绑定实际进程与目标；不把第三方 hosting/proxy 标签用于安全判定。

## 质量下降与反馈

按 degradation.md 用少量固定任务做短会话对照。记录实际可见证据与未知项，遇到配额或账号拒绝停止。提交反馈前脱敏，不上传 token、完整个人日志或账号标识；代用户发送反馈须明确授权。

来源与时效见 official-sources.md。达到当前诊断目标即停，不用真实账号制造 403/429、压力测试或持续跑分。
