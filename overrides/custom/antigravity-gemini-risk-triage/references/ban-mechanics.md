# 封禁、认证与网络风险

## 官方边界

2026-10-13 核对 https://antigravity.google/terms：个人服务条款第 6 条禁止第三方软件、工具或服务访问 Antigravity，例如 OpenClaw 使用 Antigravity OAuth，可能导致 Antigravity 和/或 Gemini CLI 账号暂停或终止。企业服务适用其管理员接受的对应条款，不能从个人条款推导全部企业入口的授权。

这不是对其他 Google 服务状态的保证，也没有给出统一恢复期限。历史解封、再认证或二振制公告不能当作当前恢复承诺。使用当前客户端显示的官方反馈/申诉渠道。

## 先分诊再处置

| 证据 | 可支持的判断 | 动作 |
|---|---|---|
| 明确 service disabled、ToS 违规或暂停通知 | 对应服务受到限制 | 暂停请求，保存脱敏响应与时间，走官方反馈/申诉 |
| 单条 401/403、permission denied | 请求被拒，原因尚未确定 | 核对认证、权限、端点、地区/资格和服务状态，不连续重试 |
| 429 RESOURCE_EXHAUSTED | 配额、频率或适用支出限制 | 查对应产品配额与等待提示；不直接判定封禁 |
| TLS/DNS/连接失败 | 链路故障的候选证据 | 核对实际进程路由与监听者；可达性不能证明账号安全 |

## 接入方式分别评估

- 官方客户端：按其资格、条款和额度使用；付费不意味着免风控或无限额度。
- 网络出口代理：改变连接路径；稳定出口有助于减少连接异常，但网络可达不证明地区资格。住宅/独享 IP、第三方 hosting/proxy 标签均不能证明安全，也不能证明封禁原因。
- OAuth 订阅复用：把 Antigravity 订阅身份接给第三方工具，落入上述条款明确限制；更换出口或模拟指纹不能改变这一点。
- 客户端注入：DLL/asar 修改属于客户端改造，不能因只做路由就宣称官方允许。优先官方支持的网络配置；修改需独立授权、备份和回滚。
- 正式 API/企业入口：使用对应服务支持的认证与计费，不把个人订阅条款或额度套用过去。

不按工具名称判定风险：同一工具调用正式 Gemini API 与复用 Antigravity OAuth 是不同路径。核对实际凭据来源、端点和调用方，不提取或打印秘密。

## 社区证据的用途

社区报错和多账号案例可以提供复现线索，不能证明封禁概率、共享 project 的因果关系、请求指纹检测机制或独享代理有效。官方未公开的机制标为未知；不据此提供规避方法。

已阅读的额度异常案例见 references/official-sources.md。日志和截图反馈须脱敏；不主动制造封禁、限流或执行压力测试。真实链路整改遵循备份、最小修改、读回、受控验证，宿主进程操作须有明确授权。
