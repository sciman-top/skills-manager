# 输出质量下降分诊

输出错误、遗漏、截断或重复工具调用需要可比较的证据。当前来源不足以证明账号风控会静默降低模型能力，也不能从 Antigravity 额度文档推导高峰时 Pro 自动变成 Flash。

## 最短排查顺序

1. 记录客户端版本、所选模型与实际返回模型标识（入口提供时）、思考等级和采样参数；界面选择只能证明选择状态，不能独立证明实际模型。
2. 用新短会话保留必要任务材料和约束，排除旧指令冲突、过量日志、摘要遗漏；没有通用的“第 20 轮必退化”阈值。
3. 固定材料、提示词和完成标准，每轮只改一个因素，少量低频对照。比较事实错误、要求遗漏和工具成功率，不以回答长短或速度判断能力。
4. 若 API 提供，检查 finishReason、usage、安全反馈、输出 token 上限；区分截断、过滤和正常完成。UI 没有这些字段时明确未知。
5. 核对工具返回、端点可用性和重复调用；失败工具或丢失进度可能导致循环。不要让 agent 无限重试相同失败。
6. 核对对应产品的额度、官方版本说明和服务状态。遇到 429、认证或风控错误停止当前任务，不为质量对照继续消耗。
7. 同条件问题可复现时，保存脱敏输入、输出、时间与复现步骤，走官方反馈。

## 参数与提示词

https://ai.google.dev/gemini-api/docs/troubleshooting（2026-10-13 核对）建议 Gemini 3.x 保持默认采样参数；低于默认值的温度可能造成循环或性能下降。不要套用“temperature=0 一定更可靠”的通用口诀。思考等级降低可能减少延迟和费用，也可能影响复杂任务质量，应按任务取舍；Antigravity 只使用其实际暴露的配置，不虚构 API 参数入口。

提示词写清目标、材料范围、验收标准和所需输出即可。减少重复或矛盾规则；开启思考时避免逐步规定内部思考过程。不把特殊口令、Canvas 模式或模型自述当作解除风控或恢复能力的证明。

## 对照记录与结论边界

记录时间、版本、所选/实际模型（不可见则未知）、参数、上下文规模、材料、具体错误、工具结果，以及可用的 finishReason/usage。可以先用 1–2 个代表任务确定是否值得进一步反馈，不建立常驻跑分或重复请求流水线。

新会话表现改善支持上下文因素的可能性；仍出错支持进一步排查产品或模型，但不能独立确认账号处罚。正式 API 与订阅客户端是不同入口，跨入口结果只能作辅助比较，不能把差异直接归因于“订阅降智”。
